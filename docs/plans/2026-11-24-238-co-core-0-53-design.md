# co-core 0.53 adoption

## Intent

Move co-core 0.51.1 → **0.53.1** in one step, the operator's call of 2026-11-24 ([amendment](https://github.com/CannObserv/replicator/issues/238#issuecomment-7122609731),
re-targeted from 0.53.0 by the [pre-build review](https://github.com/CannObserv/replicator/issues/238#issuecomment-7133391973)).
Most of the move needs no design: the alias pattern's anchor (cannobserv#763, with #232 folded
in), the vcrpy transport fix (cannobserv#603) and two docstring-only files. This doc covers the one
part that changes stream semantics, which AGENTS.md says always gets a design doc.

**cannobserv#629 makes `FetchPolicyState.generation` required on decode.** A
`content.fetch-policy` frame without one, the key missing or `null`, fails validation, and
`from_wire` raises `BusMessageAnomaly`. `fetch_policy_supersedes` keeps one rule:
`stored is None or incoming.generation > stored.generation`. Upstream decided this. What's ours is
how the consumer, its journal lines and its docs follow.

### Evidence [measured 2026-11-24]

- **The live stream has no generation-less frame.** `XRANGE content.fetch-policy - +` (granted,
  broker `deploy/redis-acl.conf`): 501 frames, 10 hosts, 501 with an integer `generation`, 0
  without. Upstream's broker#152 count was 503/503.
- **The poison path already handles it, with a real id.** On 0.53.1 a frame with `generation`
  missing or `null` raises `BusMessageMalformedPayloadError` from `from_wire` with the frame's
  `message_id`. `_skip_poison` seeks past it and logs `skipping a malformed frame on the fetch
  policy stream` at WARNING. The replay and the tail both reach it at `count=1`.
- **That WARNING doesn't say why.** Its `error` is `bus message on 'content.fetch-policy' (id …)
  has a malformed payload for event_type 'fetch_policy'`. The reason is only on `__cause__`, a
  pydantic `ValidationError` whose `errors()` give `(('generation',), 'missing')`.
- **Baseline:** 2241 passed, 2 skipped on `a5248ec`. With only the pin moved, **50 fail**,
  most because `tests/worker/test_policy.py`'s `policy()` helper defaults `generation=None`.

## Decisions

### D1. The pin: `>=0.53.1,<0.54` on all three

0.53.1 is the newest on the index. Its closure diff from 0.53.0 is `version-only` ×3, and the two
other files it changes (`pure/adapters/wordpress/transcript.py`, `pure/models/transcript_speaker.py`)
are outside the closure. The siblings at 0.53.1 require `co-core>=0.53.1`, so that's the floor the
lock forces anyway. The closure diff 0.51.1 → 0.53.1 goes into the pin comment.

### D2. A frame without a generation is poison, through the path that exists

**No local branch for it.** co-core refuses it at decode. The replay and the tail already step
past an undecodable frame, bounded by `MAX_POISON_SKIPS`. The frame is never applied, in stream
order or any other.

*Rejected: decode such a frame leniently ourselves* (catch, re-decode with `generation=None`, apply
in stream order). That rebuilds the rule upstream deleted, on a model co-core no longer defines,
to serve frames the stream doesn't hold.

**Accepted limit.** A run of `MAX_POISON_SKIPS` generation-less frames at the head of the stream
ends the boot replay early. The tail then resumes from that cursor and drains the rest, and until
it does, the hosts behind the run pace at the fallback default. That default is meant to be the
stricter number. Only a producer that stops sending `generation` could cause it, and
`FetchPolicyEmit` has required the field since #579.

### D3. `policy.py` loses the unordered rule

- `_is_current` becomes "empty slot, or `fetch_policy_supersedes`". The `occurred_at` branch
  (`:263`) is unreachable and goes, along with the stamp-pair variant of `ignoring a fetch policy
  older than the one already applied`.
- `_log_out_of_order` loses its `generation is None` branch (`:363-375`). The `without a generation
  for a host that holds one` line no longer exists.
- The module docstring's three rules become one. `_held`'s comment drops the `occurred_at` and
  ratchet clauses. Its tombstone reason stays: a tombstone keeps its `generation`, so a stale live
  frame can't bring the host back.
- `_held` is in memory and rebuilt by the boot replay, so no stored state carries a `None`.

### D4. The poison WARNING names the fields that failed (call for the operator)

**Recommendation: yes.** `_skip_poison` adds `invalid_fields` to its WARNING when `exc.__cause__` is
a pydantic `ValidationError`, as `["generation: missing"]`, one `loc: type` entry per error. It
logs **locations and error types only**, never `input` or the exception's `raw`. This applies to
any malformed frame on this stream, not only #629's. The cost is one extra and a test. Without
it, the line this change makes reachable can't tell a missing `generation` from any other bad
payload without the frame itself, and the operator has no way to read the frame.

### D5. Docs

- `docs/POLITENESS.md`: the ordering list (`:70-80`) becomes one rule. The `ignoring a fetch policy`
  paragraph (`:172-177`) names the one ordering line left, and says a frame without a `generation`
  now logs as `skipping a malformed frame on the fetch policy stream`, with `invalid_fields`.
- `docs/contracts/replicator-boundaries.md:176`: "an optional `generation`" becomes "a required
  `generation` (since cannobserv#629)". It's a description of the producer's payload, not a
  charter rule, so `tests/test_boundaries.py` is untouched (it pins neither).
- The pin text: AGENTS.md, `docs/DEPENDENCIES.md`, `.socraticodecontextartifacts.json` (plus
  `codebase_update` in the same change), and the `pyproject.toml` comment.

## Tests (TDD, failing first)

- **The behaviour change, first:** replay and tail each step past a frame with `generation` missing,
  and one with it `null`, and keep the frames behind it. The WARNING carries the frame's id and
  `invalid_fields == ["generation: missing"]` (or `int_type` for `null`). These go in
  `tests/worker/test_policy_reader.py`, on fakeredis, using the existing `pre_generation=True` raw
  publisher.
- `test_a_missing_or_null_generation_on_the_wire_is_absent` → `…is_refused_at_decode`.
- **Rewritten:** the helpers in `test_policy.py`, `test_policy_reader.py`,
  `test_policy_integration.py` and `test_main.py` build ordered frames. Tests that relied on the
  helper's `None` get an explicit `generation`. Each keeps its assertion.
- **Deleted, along with the rule they pinned:** the `occurred_at` tests (a stale republish by stamp,
  the same-stamp republish, a stale revocation by stamp) and both ratchet tests. Before deleting
  each one, I check that a generation twin already covers its assertion, and add one where none
  does. `test_a_replay_across_the_producer_handover_lands_on_archivers_state` becomes a replay with
  generation-less frames among the ordered ones: they're skipped as poison, and the map ends on
  the ordered frames' state.

## How it ships

One build PR (`Refs #238`, `Closes #232`, merge commit). Its first commit is this doc, then the
#232 and alias-import commits, which don't depend on the pin (`CREDENTIALS_ALIAS_PATTERN` is
exported at 0.51.1 too), then **the pin and D2–D5 in one commit**. The pin alone fails 50 tests,
so the two can't be green apart. #240 ships as its own PR (`Refs #238`, `Closes #240`), merged
before the deploy. **One deploy for both.** `release_set`'s diff should show only the three co-core
packages.
